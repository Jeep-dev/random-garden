批量提交助手 v0.4.2 —— 安装与使用说明

【这一版的变化】
不再模拟点击页面,改为直接调用平台接口提交:不切换标签页、不等页面加载,
页面卡住、提交按钮还没出来、甚至标签页被浏览器休眠,都能提交。

【安装】
1. 解压压缩包,得到 batch-submit 文件夹(含 manifest.json、background.js、popup.html、popup.js)。
   请将该文件夹放在固定位置,浏览器每次启动都会从此处加载扩展,不要删除或移动。
2. 在地址栏打开 edge://extensions(Chrome 为 chrome://extensions)。
3. 开启「开发人员模式」。
4. 点击「加载解压缩的扩展」,选择 batch-submit 文件夹。
5. 点击工具栏的扩展图标,将「批量提交助手」固定到工具栏。
更新版本时,用新文件夹替换旧文件夹,再在扩展管理页点击该扩展的「重新加载」。

【界面说明】
域名筛选      留空表示处理全部域名下的任务页;填写后仅处理域名中包含该文字的标签页。
处理上限      本次最多处理的任务页数量,0 表示不限。默认 1。
并发数        同时提交的任务数量。默认 1,确认无误后可调大(最大 10)。
试运行模式    勾选后只做检查,不实际提交。每次打开默认不勾选。
开始执行      立即开始,扩展窗口自动关闭。再次点击扩展图标可查看进度。

处理范围为所有窗口中的全部标签页。仅处理网址为 /editor 且带 task 参数的任务页,
主页(/operator/home)等其他页面自动排除,不计入处理上限。
处理顺序:从当前所在的标签页开始向右依次处理,到最右侧后再从最左侧处理当前标签页左边的任务页。
结果列表以网址中的任务名(task_name)标识各任务,点击某一行可跳转到对应标签页。
提交成功后,和原来点「返回主页领取新任务」一样:关闭该任务标签页并刷新已打开的主页
(批量时短时间内的多次刷新合并为一次);全部处理完后切换到主页标签页。没开主页时会在后台新开一个。

【每个任务的提交过程】
1. 读取任务信息:必须处于「质检」环节、状态为作业中(Working),否则跳过,不做任何操作。
2. 按名字查出「质检通过」对应的操作,并确认当前环节可以执行它。
3. 读取任务的标注数据(质检时为只读),原样随提交一起发送。
4. 提交,然后重新读取任务:任务已流转到下一环节才算成功。
登录令牌自动从已打开的任务页中读取,不需要手动填写。

【建议的首次使用流程】
1. 勾选「试运行模式」,处理上限保持 1,点击「开始执行」。
   结果为「预检通过」,表示可以正常提交。
2. 取消勾选「试运行模式」,处理上限保持 1,点击「开始执行」,
   到平台上确认这个任务确实已质检通过。
3. 确认无误后,将处理上限改为 0(不限)、并发数调大,批量执行。

【结果状态】
成功        已提交,且任务已流转到下一环节。
预检通过    试运行模式下检查通过,未提交。
失败        提交前出错(可点击「重试失败项」),或服务器明确拒绝了提交(任务未流转)。
待确认      已发出提交,但无法确认任务是否流转。请人工核实提交状态,切勿重复提交。
已跳过      不是质检环节、状态不是作业中(例如此前已提交)、任务无效,或已停止,未执行任何操作。

连续 3 项失败(含待确认)时自动终止,其余任务标记为「已跳过」。
已经提交过的任务状态不再是作业中,会被自动跳过,不会重复提交。

【平台变更时】
background.js 顶部的 CFG 包含操作名「质检通过」、环节类型、作业中状态等设置。
修改后在扩展管理页重新加载该扩展即可生效。
